Reading (`parseQrLink`): 10 digits → decimal, 8 characters → hex (labels printed before), other digit lengths → decimal typed by hand; 8 plain digits read as hex first and also return `idProductDecimal`, which `identify_spool` tries when the hex reading is no known product (`renderer/inventory.js`). Checked: every template's QR decodes, and the live server already redirects the 10-digit form.
- **The MCP server is called "TigerSystem.io" in AI assistants**: the local server's `serverInfo.title` (`services/mcpServer.js`, was "Tiger Studio Manager") and the Claude Desktop extension (.mcpb) `display_name` and author (`_mcpBuildBundle` in `main.js`, was "Tiger Studio Manager" / "TigerTag Project"); the extension's description no longer says read-only. - **Printed labels: the corner pill reads TigerQR+ or TigerQR** (founder's decision 2026-11-10, same change in the Hub's `lib/labels/build.ts`): a Spool Label shows TigerQR+ when its spool's reference is a catalogue product, else TigerQR; a Filament Label always TigerQR+ (`labelInfo` in `renderer/inventory.js`, `renderer/labels/index.js`). - **Analytics follow the shared event contract v2** (TigerTag-Manager `docs/analytics.md`, validated 2026-11-10): every event gets `V: 2`, an `EventId` (UUID v4) and a `Session` (random per launch, renewed after 30 min in the background: no window focused, machine asleep or locked); chip events get `Reader: usb_reader` and `Device`, the reader model (`ACR122U`). New operations `app_open` (launch / back after 30 min, once per session, a window reload counts none) and `catalog_view` (a catalogue product card opened in Search, `IdProduct` + `Surface: studio`, one per product per 5 min), both behind the kill switch `ANALYTICS_V2_OPERATIONS` (on: Xano accepts them since 2026-11-10). No `IdProduct` 0 / 4294967295 on read / write events any more (`_xanoChipFields`), no `SpoolId: ""`. An event that failed on the network or a 5xx is kept with its `EventId` and `Timestamp` in `<userData>/analytics-resend.json` and sent again for 7 days (not a 4xx, never `online`); what is still queued at quit is kept too. `_analyticsStats.sent` now counts accepted events only (a rejected one was counted as sent), plus `resendPending`; the diagnostic report line says "accepted · … · to send again". New `services/analytics.js` (`stampEvent`, `AnalyticsSession`, `readerModel`, `shouldResend`, `ResendStore`), tests `scripts/test-analytics.mjs`; `main.js` queue + IPC `analytics:app-open-due` (preload `analyticsAppOpenDue` / `onAnalyticsAppOpenDue`); `renderer/inventory.js` `_sendAppOpen`, `_sendCatalogView`; `docs/ANALYTICS.md`.
- **Analytics events carry the chip UID in hex too** (asked from the Manager / Xano side, 2026-11-10): every event with a `Uid` also sends `UidHex`, the UID as printed (uppercase, whole bytes, e.g. `04D8593DD42A81`), `online` / product/get included; `Uid` stays decimal as before; TigerData / TigerData+ send neither. Xano stores the UID as a 64-bit integer and a decimal past 2^53 loses digits; Xano reads `UidHex` first since its change 43 (live 2026-11-10). `analyticsUid()` in `renderer/uid-repair.js` replaces `_xanoUidDecimal` (`renderer/inventory.js`), tests in `scripts/test-uid-repair.mjs`; `docs/ANALYTICS.md`, the `main.js` analytics comment.
