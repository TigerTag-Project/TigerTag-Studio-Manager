# Worklog — v2.27.4 (in progress)

## Added
- **Russian, the 10th locale** — `ru.json`, 1523 keys, contributed by @Ptitlouis6012 in #31 and merged as theirs. Wired into the language picker, the onboarding step, the locale loader and the three i18n scripts; the doc-drift checker now COUNTS the locale files instead of holding "9" as a constant, which is the part that keeps the next locale cheap. Reviewed before merging: key set identical to `en.json`, no empty value, every `{{param}}` preserved, the 19 plural objects and 6 arrays kept as such, and the tone held — the translation avoids ты/вы entirely through impersonal forms, which is the safe register in Russian.


## Changed
- **The Firebase Explorer browses the Realtime database too, in its own tab.** Firestore and the Realtime database are two services, and only the first was reachable — so a TigerScale's command channel, which is where the app and the device actually talk, could not be looked at from the app at all. A Firestore / Realtime switch sits above the chips; the Realtime side is read over REST with the signed-in user's ID token (no SDK for it is loaded). Every node is probed with `shallow=true` first, which answers the child NAMES for a branch and the value itself for a leaf: a branch of 25 children or fewer is then read in full, anything larger stays a list to drill into, so no stray click can pull a whole tree. Measured against the real database: the rules there are per-NODE — `scales/{mac}/cmd` reads, `scales/{mac}` and `scales` are denied — so the chips are built from the scales the account owns and point straight at the readable node, and a denial says what it means rather than "error". Verified on a real scale: the chip lands on `scales/206ef19a17b4/cmd` and shows the last command the app sent it — `renderer/inventory.{html,js}`, `renderer/css/70-detail-misc.css`
- **The Firebase Explorer reaches the TigerSpools**, the collection a TigerSpool writes itself into from firmware 1.65.0 (`users/{uid}/tigerspools/{mac}`, keyed by the Wi-Fi MAC). Presence only, which is all the device publishes today; the app does not list the boxes yet. Reading it is also the fastest way to answer whether a box is declaring itself at all — and the first thing it answered here is that the rules deny the path entirely — `renderer/inventory.js`
- **The Firebase Explorer reaches the scales, the racks and the lists.** Its quick chips covered the inventory, the printers and the products but stopped there, so a TigerScale's document — the one holding what the firmware reports about a physical device — could only be seen by typing its path by hand, which means knowing it. Three chips added: `scales`, `racks`, `lists`. A scale's live command channel (TARE) is in the REALTIME database rather than Firestore, so it stays out of reach of this explorer by nature, and the chip comment says so — `renderer/inventory.js`
- **Debug mode is every account's switch, not the admins'.** The toggle in the account modal was shown only to `roles: "admin"`, and `state.debugEnabled` was itself `isAdmin && Debug` — so a normal user could never turn on the one view that makes a bug report useful (their own raw Firestore documents, the last call to the API, the per-card "copy ref" helper). The gate bought no safety: the panel reads the SIGNED-IN user's own documents and every path goes through the same Security Rules as the rest of the app — the checkbox was never what stood between a user and someone else's data. The row is always shown now and `Debug` is read as the plain user preference it is; `roles` still gates the Admin badge, and nothing else. The panel button itself was already unconditional — `renderer/inventory.js`, `CLAUDE.md`
- **The "What's New" tooling knows about locales that arrived late.** Adding `ru` to the three whatsnew scripts alone would have failed the whole back-catalogue: the check demands that an item which carries ANY non-English locale carries them all, and 507 items written before Russian existed carry none. A `LOCALE_SINCE` map (`{ ru: "2.27.4" }`) now says which version a locale shipped in, and each version block is held to the locales that existed then — history stays valid, everything from v2.27.4 on must be complete in all 10. `whatsnew:add` scaffolds 10 locales, and `whatsnew:import` recognises a Russian entry as hand-localised so it is never overwritten — `scripts/whatsnew-{add,check,import-changelog}.mjs`
- **Seven Russian plurals corrected** (kept in the contributor's own style, which sidesteps the problem elsewhere in the file): Russian has three plural forms where the app's engine has two, so "{{n}} материалов" is wrong for 2-4. The counts now read "Материалов: {{n}}", "Друзей: {{n}}", "Подписчиков: {{n}}" — the impersonal form the translation already uses for loaded spools and hidden items — the durations use the invariant abbreviations "{{n}} сек" / "{{n}} мин", and the rack tile's label, which sits under its own number, is the plain plural "стеллажи" — `renderer/locales/ru.json`
- **The printer speed dropdown sizes itself to its own label.** Found by running the app in Russian: a fixed 110 px (96 px on Anycubic) clipped "Сбалансированная" to "Сбалансирова…" — the width had been tuned to the English "Standard", and every locale is free to be longer. It now sizes to its widest option, floored at the old width so no other locale moves, and capped so a long label cannot push the card — `renderer/css/57-elegoo.css`, `renderer/printers/anycubic/anycubic.css`
- Locale counts updated wherever a doc or a comment stated nine — `CLAUDE.md`, `README.md`, `FEATURES.md`, `ROADMAP.md`, `renderer/CODEMAP.md`, `renderer/inventory.js`, the four `docs/*-BRIEF.md`
